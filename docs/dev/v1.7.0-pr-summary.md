# v1.7.0 PR Summary

## BL087: HyperPod EKS instance-role IAM fixes

- Verified the existing `MlccEksClusterStack` implementation compiles and emits the HyperPod instance role with both SageMaker and EC2 trust principals.
- Added unit coverage for the four required managed policies, ENI-management inline policy, lifecycle-bucket S3 read policy, and Fargate pod execution-role retention.

- Verified the bootstrap TypeScript build and HyperPod CDK/bootstrap integration suites.

## BL088: HyperPod EKS InferenceEndpointConfig CRD migration

- Migrated the HyperPod EKS deployment target from raw Kubernetes `Deployment`, `Service`, and `ConfigMap` manifests to a single `InferenceEndpointConfig` custom resource (`templates/hyperpod/InferenceEndpointConfig.yaml.ejs`), reconciled by the `amazon-sagemaker-hyperpod-inference` operator. Removed the legacy `deployment.yaml`, `service.yaml`, `configmap.yaml`, and `pvc.yaml` templates — the operator now provisions the serving workload and model storage.
- Verified the CRD schema against `kubectl explain inferenceendpointconfig --recursive` and the AWS docs before implementation: `spec.worker.environmentVariables` (not `spec.worker.env`), `spec.modelSourceConfig.s3Storage.{bucketName,region}` (parsed from `STAGED_MODEL_PATH`, not a full `s3://` URI), and required `spec.modelName`. Confirmed `spec.worker.args` and `spec.worker.environmentVariables` both exist, unblocking BL085's speculative-flag injection.
- Rewrote `do/deploy.d/hyperpod-eks` to render the model source conditionally (S3 when staged, otherwise Hugging Face with a `hf-token-secret` `tokenSecretRef`), apply the CRD, poll `status.state` until `DeploymentComplete`, then poll `aws sagemaker describe-endpoint` until `InService` (15-minute cap). On success it writes `ENDPOINT_NAME=$PROJECT_NAME` and sets `DEPLOYMENT_TARGET_HP_STATUS=Running` only after `InService`; failure/timeout records `Failed`.
- Updated `do/clean.d/hyperpod-eks` to delete the `InferenceEndpointConfig`, wait for the `SageMakerEndpointRegistration` to be removed, and clear `ENDPOINT_NAME`.
- Preserved workflow compatibility: `do/test --target hyperpod-eks` resolves and port-forwards the operator-created Service (defaulting to the project name), `do/logs --target hyperpod-eks` falls back across operator pod-label conventions, and `do/benchmark` targets the registered endpoint directly (no inference component).
- Added `.ejs` suffix stripping to the template copier so `*.yaml.ejs` renders to `*.yaml` in generated projects and via `mcc regenerate`.
- Updated and added regression coverage: migrated the raw-manifest property/unit tests to the CRD contract, added `hyperpod-crd-deploy-driver.test.js` for the deploy/clean driver contract and S3/HF model-source rendering, and re-homed the manifest-side speculative tests to BL085 while keeping the serve-script guards. Full JS suite and `uv run pytest test/unit/` pass (pre-existing, environment-only `notebook-export` and cluster-picker subprocess timeouts excluded).
